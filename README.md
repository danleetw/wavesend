# wavesend

用聲音把檔案從一台裝置傳到另一台。無網路、無配對、無伺服器、無安裝。

**開啟：** https://danleetw.github.io/wavesend/

單一 HTML 檔案，零外部相依。存到本機也能離線使用。

## 怎麼用

1. 兩台裝置各開一次這個網頁
2. 一台選「傳送」、一台選「接收」，**模式、調變、密碼三者都要一致**
3. 接收端先按開始，發送端再選檔案並開始
4. 接收端湊夠資料會自動完成、解密、驗證，然後跳出下載連結

**手機必須貼在喇叭上 2–3 cm**，麥克風端對準、墊軟布隔開桌面。這不是建議而是必要條件：
實測 10–30 cm 時房間混響的延遲擴散是 18 ms，而系統的 cyclic prefix 只有 2.3 ms，
差 8 倍，完全解不開。貼近後混響在 1 ms 內衰減到 −30 dB。

## 兩種模式

| 模式 | 頻帶 | 速率 | 聽感 |
|------|------|------|------|
| Stealth | 18–22 kHz | 約 590 B/s | 幾乎無人聽得見 |
| Turbo | 2–22 kHz | 約 2970 B/s | 像數據機撥號 |

10 KB 在 turbo 約 3 秒、stealth 約 17 秒。100 KB 分別是 34 秒與 2.9 分。

聲學傳輸的實用上限大約在 10 MB 等級。再大請用實體媒介 —— 10 GB 在 turbo 需要 42 天，
而即使做出打到 Shannon 極限的完美 modem 也要 6.6 天。這是物理限制，不是實作問題。

## 加密

檔案與檔名都用密碼加密：PBKDF2-SHA256（210k 迭代）導出金鑰，AES-256-GCM 加密。
沒有密碼的人即使錄下全部音訊也解不出內容，密碼錯誤時 GCM 的驗證標籤會直接擋下。

這**不是**「輸入密碼才能開啟網頁」那種閘門 —— 這是公開的靜態網頁，
任何前端閘門的密碼都寫在原始碼裡，看原始碼或關掉 JS 就能繞過，等於零安全性。
有意義的是加密內容本身。

## 技術

OFDM，48 kHz 取樣，FFT 1024，副載波間距 46.875 Hz，符元 24 ms。
chirp 前導做同步，PI 迴路追蹤收發時脈差（實測可鎖 0–500 ppm）。
削峰濾波把 PAPR 從 18.7 dB 壓到 12.6 dB，符元邊緣做升餘弦漸變與重疊相加
（少了這個，符元接縫的階躍會在 2–4 kHz 灑出 −44 dB 的可聽噪音）。

傳輸層用 LT 噴泉碼：發送端持續產生全新的封包，接收端收到任意約 1.1–1.6 倍 K 個
就能還原。不需要回傳通道、可以中途加入、掉包只是變慢不會出錯
（實測掉 40% 封包，需要收到的總數幾乎不變）。
CRC-16 偵錯把位元錯誤通道轉成抹除通道，交給噴泉碼處理，因此不需要另一層 FEC。

未編碼 BER 貼合理論曲線 0.9 dB 以內。

## 瀏覽器需求

需要安全來源才能存取麥克風。https（本頁）與 Android Chrome 的 `file://` 都可以；
桌面版 Chrome 會擋掉 `file://` 的媒體存取，本機使用請走 `http://localhost`。
